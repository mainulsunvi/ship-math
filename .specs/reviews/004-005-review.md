## 7. Open question — 004 criterion 6 (`findMatchingZones` priority order)

**Recommendation: amend the spec, and add the pure helper without a priority column.** Zone
matching is a per-rule gate; precedence in 005 is rule priority, so a zone-priority column is
dead weight (and a migration) in MVP. Add `findMatchingZones(zones, destination): WireZone[]` as
an input-order-preserving filter (stable, documented as "caller-defined order — loaders order by
createdAt"), and reword criterion 6 to "returns matching zones in input order and is stable". If
008's simulator trace later needs explicit zone precedence, revisit with a column then.
